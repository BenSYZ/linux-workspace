为什么 sata 盘用的还是 ide-hd？

这是一个非常经典且容易让人产生误解的命名历史遗留问题。
简单直接的答案是：在 QEMU 的源码和架构设计中，ide-hd 代表的是“ATA 协议的硬盘前端驱动”，而不是指那根古老、很宽的 IDE 并口排线（PATA）。
因为 SATA（Serial ATA）和老式 IDE（Parallel ATA）在底层共享了几乎相同的 ATA 指令集，所以 QEMU 开发者为了复用代码，让它们共用了同一个设备前端。
下面是深层原因剖析：
## 1. 软件协议与物理接口的解耦
在计算机硬件中，我们需要区分协议（软件看什么）和控制器/总线（硬件怎么连）：

* 指令协议： 无论是 1995 年的宽排线硬盘，还是 2010 年的 SATA 固态硬盘，它们和操作系统沟通的语言都是 ATA 指令（如 READ SECTORS, WRITE SECTORS）。
* QEMU 的设计： ide-hd 模拟的正是这个“支持 ATA 指令的物理硬盘实体”。它只负责处理硬盘本身的读写扇区逻辑、缓存逻辑等。

## 2. 靠 bus= 决定它是“老 IDE”还是“现代 SATA”
ide-hd 本身只是个硬盘，它必须插到控制器总线（bus）上。正是你指定的 bus 参数，决定了这块盘走什么通道：

* 当你插在旧控制器上：
-device ide-hd,bus=ide.0
此时，QEMU 把这块 ATA 硬盘连到了传统的 PATA (IDE) 控制器上，系统里走的是旧驱动。
* 当你插在现代 SATA 控制器上（如 q35 自带的 ahci0）：
-device ide-hd,bus=ahci0.0
此时，QEMU 把这块 ATA 硬盘连到了现代的 AHCI (SATA) 控制器上。虽然前端设备依然叫 ide-hd，但由于总线变为了 ahci0.0，数据流会全部通过 PCIe AHCI 协议传输。虚拟机内部的 Linux 内核会极其敏锐地发现这一点，并加载现代的 ahci 驱动，将其识别为 sda。

## 3. 为什么不重命名一个 sata-hd？
QEMU 作为一个发展了 20 多年的开源项目，非常注重向后兼容性和代码复用。
如果单独写一个 sata-hd，其内部 95% 的代码（处理镜像读写、磁盘几何结构、ATA 状态机等）会和 ide-hd 完全一模一样，属于严重的重复造轮子。因此，QEMU 保持了 ide-hd 的命名，只通过扩展它的 bus 兼容性来支持 SATA 控制器。
------------------------------
## 🔍 顺带一提：真正的 SCSI 盘用什么？
作为对比，你可以看看 QEMU 对其他协议的命名，逻辑是完全一致的：

* ATA 协议： 无论新旧，前端一律用 ide-hd（可以插在旧 IDE 总线或现代 AHCI 总线上）。
* SCSI 协议： 无论新旧，前端一律用 scsi-hd（可以插在虚拟的 LSI 控制器、Megaraid 阵列卡或现代的 virtio-scsi-pci 总线上）。

所以，看到 ide-hd 别害怕，只要你把它插在 ahci0.0 上，它在虚拟机里就是百分之百的纯正 SATA 盘！
